# Gitとは何か

## 今日学ぶこと

- Gitが何をする道具なのか
- コミットとは何か
- ブランチとは何か
- GitHubとの違い

## Gitは変更履歴を記録する道具

Gitは、ソースコードの変更履歴を記録するための道具です。

コードを書いていると、昨日の状態に戻したくなったり、誰がどこを変更したか確認したくなったりします。

Gitを使うと、そういった変更を順番に記録できます。

## コミット

コミットは、ある時点の変更を保存することです。

ゲームでセーブする感覚に近いです。

ただしGitのコミットは、ただ保存するだけではなく「何を変えたか」「なぜ変えたか」を後から確認できるようにします。

## ブランチ

ブランチは、作業場所を分けるための仕組みです。

たとえば本番用のコードを壊さずに、新しい機能を別のブランチで作れます。

開発現場では「この修正は別ブランチで作業して」と言われることがよくあります。

## GitとGitHubの違い

Gitは変更履歴を管理する道具です。

GitHubはGitのデータをインターネット上で共有するサービスです。

つまり、Gitは仕組み、GitHubは置き場所と考えると分かりやすいです。

## 実際の開発では

現場では、まずこの流れをよく使います。

- branchを切る
- コードを修正する
- commitする
- pushする
- pull requestを作る

最初は全部を完璧に覚える必要はありません。

まず「Gitは変更履歴」「GitHubは共有場所」と覚えましょう。

## まとめ

- Gitはコードの変更履歴を記録する道具です。
- コミットは変更のセーブポイントです。
- ブランチは作業場所を分ける仕組みです。
- GitHubはGitのデータを共有するサービスです。
